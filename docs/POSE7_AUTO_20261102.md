# 2026-11-02 自动定位 PCB 配套版本

本版由 pose7 CCL 副板和 auto_compat 主板组成。工程与 bit 位于 [hardware_versions/20261102_pose7_auto](../hardware_versions/20261102_pose7_auto/)，2026-11-01 固定窗口版仍保留在 hardware/。两组版本分别记录 SHA256 和实板状态。

## PCB 流程与操作

主板选择 SW4:SW3=01、SW2=1，按下 KEY4 并完成消抖后接受一个识别任务。长按不连续抓拍，忙碌期间不排队，松开不取消已经接受的任务。

副板分时复用灰度 CCL，选择面积最大的 PCB 候选，按模型公式采样 96×96 源 Y8。两个方向缩略图用于选择 0/180°，随后执行一次 1→4→4 编码器和良品空间异常评分。该流程不要求 PCB 严格放入旧固定框，但仍需要完整、合法的候选边界。当前不支持任意旋转或透视配准。

| 异常分数 | 结果 |
| --- | --- |
| ≤106 | PASS |
| 107..204 | REVIEW |
| ≥205 | FAIL |

分数不是置信度百分比。无候选、标签溢出或源边界坏框返回 REVIEW 并清除旧框。当前不发布缺陷定位，defect_count=0；不能把整个候选框解释为缺陷范围。

主板显示副板返回的原图候选框，并将右、下端独占坐标转换为 HDMI 包含坐标。左下角状态面板继续显示 PCB 结果。PCB 使用 Type8，普通检测使用 Type18；REVIEW 的 checked=0，不应显示为 FAIL。

接收 FRAME_ACK 后，主板 PCB 结果等待预算为 30 秒，普通 CNN 为 2 秒。250 ms 心跳与 3 秒链路租约分别保持；只有匹配当前 session/frame/job 的结果才被接受，重复完成包只补 ACK，不重新识别。

## 普通 CNN 与写字功能

普通 CNN 的 9 类、权重和 FC_CONF_SHIFT=8 保持不变。首次合法候选发布当前框、类别和实际分数，并标记 uncertain；连续三次确认类别，短暂跳类可保留已确认名称，分数不抬高。无目标时不发布旧框，KEY1 使用独立锁存快照。

为改善 RAM→DSP 时序，副板增加成对 operand 寄存与 d2 对齐；每个 ROI 增加 49,155 cycles，即约 0.39324 ms@125 MHz。27 个 ROI 的整数值与修复前参考一致。

文档 4×4 输入判定、骨架与路径规划、矢量字模、统一一次 X 镜像、自动换行、KEY1/KEY2/KEY3/KEY4、GRBL 及断网后保持已接受任务继续保留。按键和接线见 [硬件与控制](HARDWARE_AND_CONTROL.md)。正常末条 ok 是命令接收确认，不是机械 Idle。

## 核验与构建

在完整仓库根运行：

~~~powershell
python -B verify_release.py
~~~

该命令分别校验两组归档；也可在新版包根单独运行 python -B verify_package.py。校验覆盖完整文件集合、字节数、SHA256、冻结输入映射和 bit 身份。主板 138 条、副板 83 条 File 引用均在各自目录闭合。

仅根工程入口路径做相对化，RTL、模型、约束没有修改。构建请先复制到独立短英文路径；保留 IP、初始化文件、include 和运行目录布局。原始 runs/evidence 脚本、项目及日志包含开发机路径，需先适配，不能直接当作跨机器一键构建入口。本次归档没有重新综合或生成 bit。

配对实板状态为 **NOT_RUN**。旧版通过声明绑定另一组 bit，不能沿用。642 帧开发集回放只证明参考一致性；行为 DDR reader 仿真不代替厂商 PHY 电气验收，抽象 reader 下的处理时间也不是网络到写字机的完整耗时。仍需实测独立良品/缺陷、位置/角度/光照、PASS/FAIL/REVIEW 显示、CNN、文档、断网保持、停止与复位，并复核 30 秒预算。
