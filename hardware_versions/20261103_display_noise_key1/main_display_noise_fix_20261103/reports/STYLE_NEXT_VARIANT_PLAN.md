## 3. 分阶段增强方案

### S1：先修复现有算术

仅合并SATU有符号半差、GAML单调分段和RAIN明确字节宽度。保留0..18模式号、全部端口、帧锁存、流水级和吞吐量。目标是替换现有表达式，DSP与BRAM不增加；LUT／进位链成本和时序需实际综合确认。

先让这一独立阶段通过全部19模式及固定识别tap回归，再合入视觉增强，避免算术修复与新空间算法相互掩盖。当前V7不会接入S1。

### S2：利用现有轮廓计算增强边缘

首选复用已经活动的`cartoon_96`四路逐像素灰度、左／上邻居和`320×32 bit`行RAM，让模式7／8可输出逐像素因果梯度；不新建完整3×3窗口。

1. 模式7／8在上游保留原逐像素RGB，送入现有renderer；renderer用内部帧锁存的效果选择区分原图旁路、边缘、反色边缘和CART。该内部选择不新增顶层／网络模式号。
2. 继续使用`g=abs(C-L)+abs(C-U)`。候选显示式为`e=sat8(max(g-deadband,0) << gain_shift)`；模式7输出`e`，模式8输出`255-e`。先离线比较deadband=12／16／24，gain_shift=1／2；16与1只是试验起点，不是已批准生产参数。
3. 用新路径替换旧7／8组域Sobel运算，不同时保留两套大分支。浮雕与形态学仍需原组域窗口，不能声称删除所有旧行RAM。
4. 这比旧组域边缘有更细的横向采样，但其算法是**因果左／上梯度，不是完整3×3 Sobel**。若替换，应同步把该风格的显示名称改成能准确表示算法的EDGE／反色边缘，不继续用SOBL误导用户。
5. 保持现有一输入一输出节奏、相同流水延迟与ready/valid。第一行／列、lane3→下一组lane0、帧起点和停顿后邻居连续性必须明确定义并逐像素验证。

低资源备选：若复用renderer的新增选择逻辑仍超时／超资源，仅对旧组域Sobel增加deadband及2倍增益，保持其4像素粒度，并明确交付限制。不能通过低阈值宣称获得新细节。

### S3：二值化稳定性

先把模式2的固定128提取为独立内部编译参数，用同一批明／暗实拍比较96／112／128／144／160。完整保留每像素比较，不能先对四像素求平均后统一二值。此阶段不改变公共亮度公式；历史近似亮度白端236，选阈值时必须按实际域统计。

若固定阈值在明暗场景仍无法兼顾，再单独评估**实际style输入域**的稀疏亮度标量估计，上一帧完成后锁存下一帧阈值，限制变化速度及范围。初始比较范围64..192、背景偏移8..16；具体参数以样本结果决定。不得把RAW AE平均值直接当作post-AWB RGB亮度。该方案只能适应整体亮度，不能承诺消除局部阴影。

不同时加入Otsu直方图、大窗口局部均值、完整连通迟滞或逐像素除法器。局部阴影仍严重时，应另立资源和算法评审，不能塞入“改一个阈值”的交付范围。二值化只改变显示风格，不能用于宣称副板文档提取算法获得改进。

### S4：卡通轮廓与色阶

- 复用现有逐像素轮廓和同一个行RAM，比较阈值24／32／40／48。阈值降低会同时放大颗粒轮廓；远景颗粒明显时不能把“更强”简单定义为降低阈值。
- 保持8级色阶，评估把3位等级扩展到完整8位：`{q3,q3,q3[2:1]}`，输出0／36／73／109／146／182／219／255。它保留白端255，替代当前E0截断后的最大224。此映射是选定效果的设计，不能加到ORIG、识别输入或其它模式。
- 可离线比较4级色阶0／85／170／255，但不默认采用；减少色阶是卡通效果，不是常态画面降噪方案。
- 当前HDMI保边滤波位于风格处理之后，不能清除上游已经生成的黑色假轮廓，不能把它当作CART前置降噪。若要加前置弱去噪，必须另行衡量共享邻域成本并验证细线／文字保留，当前方案不新增该支路。

## 4. 资源与实现边界

仅以最终真实place／route报告验收。原成功`main_pcb_auto_compat_20261101`为19715／21216 Slice（92.925%）、90／108 ERAM、37／40 DSP，setup WNS +0.384 ns，hold +0.020 ns。V2／V3／V4／V5／V6降噪尝试均真实发生PHY-7027／PHY-9002布局容量失败，没有通过布局。V7正以同一CD722空间RTL、`pack_effort high`和`map_mode area_prior`重新独立构建，尚无最终物理结果。综合Slice*的算术余量不是可任意使用的物理预算，不能据此承诺可用余量或新bit。

- 目标：**DSP增量0，ERAM增量0，不新增帧存储／视频FIFO。** 现有37／40 DSP已使新增1个DSP触及95%，不允许通过放宽严格小于95%的门槛解决。
- 优先替换表达式、共享既有梯度、用移位和布线实现增益／色阶。空间算子先做减法、阈值和mux成本估算；通过综合也必须继续检查真实SLICEL／SLICEM打包容量。
- 不启用未在活动层次中的`cartoon_sobel_96`、`style_video_96`、旧`denoise_96`。旧wrapper含512×103队列及合成尾行／drain，历史注释已记录它改变现场帧节奏、导致CART滚屏。不能以文件已经存在为理由重新打开。
- 不增加DDR读写端口、完整帧TNR或额外DMA，不改设备型号、时钟／IO约束或既有告警解释。若继承`pack_effort high`和`map_mode area_prior`，必须沿用最终成功快照及有文档支持的单行配置，重新核对真实执行和后端拥塞。
- 保持setup/hold WNS≥0、TNS=0、Slice<95%、ERAM<90%、DSP<95%；任何一项失败则保留独立RTL／日志／报告，不生成不合格bit。

### 算术修复是否能顺带省资源

初始只读来源为V5的`camera_to_dsi_display_720p60_cnn_multibox_gate.area`，现有style层次为1230 logic LUT、344 ripple、1093 seq、2 ERAM；其中CART子层次为226／72／268／1，父子不能相加当作总资源。这是**全工程中的未修复style综合报告**，不是候选结果或物理占用，不能与后面的独立wrapper计数交叉相减。

| 候选 | 静态机会 | 不能据此宣称的收益 |
|---|---|---|
| SATU符号修复 | 把错误零前缀换成符号扩展，主要是布线变化，不引入DSP／RAM | 活动SATU并非32位：目前`delta/offset/adjusted`已经是10位；不能宣称“32→8所以节省大量资源” |
| SATU／共享增强位宽收紧 | 数学上差值范围−255..255需要9位有符号，半差需要8位有符号；其它共享offset也能落在8位范围。可以独立评估9位delta、8位offset | adjusted范围可达−128..382，仍需要10位有符号；不能把它裁成8位。综合器可能已经删除冗余符号位，所以源码少两位不等于实际少carry |
| RAIN显式8位ramp | 候选使用`{gray[5:0],2'b00}`、按高2位选择、8位取反；ramp本身不需要减法／加法。它取代原32位常量运算与多层三目式，是清晰的源级简化机会 | 原综合网表可能早已裁掉高位或化简常数；原错误还丢失了一些颜色通道，修复会恢复逻辑。下面实测的是三项修复合计成本，不能从中推断RAIN单项收益 |
| GAML单调修复 | 继续共享原10位最终加法器和夹位；分段选择由输入高位决定 | 已验证候选为正确offset增加了小加法式，可能增加LUT／carry。它的正确性已通过，不代表资源更低。可另评估布尔化offset或直接分段输出，不能盲目给12个通道各增大ROM |

## 5. 原图、识别、运动及链路契约

原图模式0对最终成功噪声版保持像素和握手一致；不修改AE／AG／DG、AWB、LSC、BLC、CCM、tone、当前HDMI降噪或OSD布局。

CNN／PCB／文档固定快照来自`tone_fixed_O_tdata → O_clean_rgb`，位于style之前。保持该连接和模型权重、HXA1／Type18／Type15格式、PCB30秒预算及250ms心跳、KEY4单次启动、DDR协议、副板UART／GRBL行为。每种风格的ready/valid与标志必须维持一对一，不通过额外反压间接改变固定tap的接受事件。

现有运动采样读取显示DDR的`S_video_rd_data`，在HDMI空间滤波之前、风格运算之后。因此增强边缘／二值／卡通会改变运动算法看到的像素。保留运动RTL和参数不等于保证这些风格下的运动事件不变。须加入逐风格运动回归并报告差异；本方案不偷偷改运动源。如果用户要求风格与运动输入完全独立，应另行明确数据源及资源设计。
