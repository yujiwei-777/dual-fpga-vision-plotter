# 工程打开与开发

Windows；Tang Dynasty Release 2026.1 SP2 / 6.2.200067；PH1P35MDG324，speed -3。Python 3.11+ 用于校验和准备开发副本。RTL 仿真工具及厂商 IP 仿真库需自行安装。

1. 将包解压到短英文路径。
2. 运行 `python -B verify_package.py` 校验原件。
3. 运行 `python -B prepare_projects.py D:/fpga/dev_suspect_paper`。目标必须是不存在的新目录。脚本只在该新目录复制工程、改写 AL/PRJ 的项目根路径并补充等字节 ROM 别名，不修改交付包。
4. 按脚本打印的路径打开两个工程；顶层分别为 design_top_wrapper 和 secondary_top。

原始工程入口：

- 主板 `02_projects/main/01_rtl/imgq_gain_m/main/td_project_display_noise_v8/camera_to_dsi_display_720p60_cnn_multibox.al`
- 副板 `02_projects/secondary/runs/syn_1/secondary_cnn_multibox.al`

所有 File 引用保留原相对层级。原始 AL/PRJ 中的 E 盘历史 Path 用于核对成功构建；准备脚本在开发副本中替换为实际位置。原始 RTL、约束、ROM、模型不改写。不要直接双击未适配的历史入口后向旧构建目录写入。

## 构建入口

准备脚本生成 `build_main_synth.tcl`、`build_main_place.tcl`、`build_main_route.tcl` 和对应 secondary 文件。TD 命令环境从这些入口启动，脚本切换至原构建所用相对目录后执行原 Tcl，保留 CDC、复位、KEY3 等约束/证明步骤。按 synth → place → route 顺序运行；不能改用默认 GUI 策略后视为同一构建。脚本不执行 bitgen。

普通 CNN 的有效权重是 `model/export/`；PCB 二分类为 `model/experiments/conv4_4/`，疑似区域辅助数据在 `model/suspect/`。冻结工程还带有未启用模型，不要凭目录名误认为启用了 pose7/goodonly。副板 `$readmemh` 混合使用 `model/...` 与 `../model/...`；准备工具会检查并补齐原启动目录下的等字节 ROM，不应任意移动文件。

仿真台、测试向量及运行脚本保留在各工程 tests、reports、tools；历史脚本可能固定原机器工具路径或基线对照路径，重跑前按脚本参数及证据清单适配。它们不是一条命令即可跨机器复现的整板仿真套件。

本次仅核验交付文件、工程引用及 ROM 路径，没有在接收方机器重建。原生工具、IP 和许可证另行安装。重建须重新验收时序/资源、DRC、CDC/FIFO/DDR、只读 reimport；不保证逐 bit 一致。完整包 `05_build_archive/` 保留成功构建数据库与原始日志。历史报告中的旧路径保留作证据，不作为文件缺失或当前活动工程的依据。
