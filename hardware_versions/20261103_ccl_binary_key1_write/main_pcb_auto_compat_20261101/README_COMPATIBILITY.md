# 自动定位 PCB 副板配套主板

本独立工程基于 `main_osd_brightness_20261101` 的成功亮度主板。原工程、原 bit、模型、副板和 `work/` 均保持不变。

## 配套行为

- PCB KEY4 一次按下只接受一个任务，持续按住不重抓帧。忙碌期间的多余按键不排队；松开不取消已接受任务。
- 完整图像和原有 HXA1 格式保持不变。接收当前帧 FRAME_ACK 后，PCB 使用独立 `PCB_RESULT_TIMEOUT_MS=30000` 预算，普通 CNN 仍为 2000 ms。
- PCB 等待计数在心跳及缓存结果 ACK 的发送子状态中继续累计，不因有效收包或发送心跳而重置。250 ms 心跳和原有 3000 ms 链路租约各自保留。
- 只接受当前 session/frame/job 的结果；重复已完成结果只补发 ACK，不重抓帧、不再次提交。
- PCB 检测框显示副板 Type8 返回的原图坐标，右/下端独占坐标转换为 HDMI 包含坐标。不再用固定放置框冒充检测结果；无目标时无检测框。左下角 PCB 状态面板保留。

## 超时预算限制

30000 ms 是可配置的初始预算，不是测得的完整副板最坏耗时。副板当前自动搜索保守上界约 9.547 秒，尚不包含细配准、最终 DDR 重采样和缺陷检查。配对实板验收仍须测量从 FRAME_ACK 到最终结果的完整耗时，并据完整上界与通信裕量复核此参数。不能用延长 PCB 预算掩盖真实 PHY 或链路租约失效。

## 基线来源

基线 bit SHA256：`FB3FE4F57721C7068821EC0C010D589CB82398E6F38CCCF3F7892006033E5515`。基线继承的旧 no_hist 快照不是亮度版构建前快照；`reports/recovered_brightness_baseline_manifest.json` 明确记录事后重建证据及其限制。本工程必须另外生成自己的构建前完整依赖快照。亮度曲线常量 52 保持基线值，不另调图像处理。

硬件状态：`NOT_RUN`。构建、仿真和交付结论以本工程新生成的报告为准，不以复制来的历史报告为本次证据。
